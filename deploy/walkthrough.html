What you need

Blank SD card to apps that start on every boot. Work through each step; checks save in this browser.

Hardware & software

Flash the OS

Use Raspberry Pi Imager. Enable SSH so you can install without a keyboard on the Pi.

Imager steps

  1. Choose Raspberry Pi OS — Bookworm, 64-bit. Lite is fine.
  2. Open the gear / OS customisation:
  • Hostname stonepi (optional — the installer can set it)
  • Enable SSH (password or public key)
  • Set username + password (you will use these for SSH)
  • Configure Wi‑Fi if you are not using Ethernet
  1. Write the image to the SD card.

Copy StonePi onto the SD card

After Imager finishes, Windows often remounts only the small boot partition. The big “unreadable / needs format” volume is Linux root — ignore it.

Find bootfs (FAT), not the Linux partition

A Pi image has two partitions. Windows can only open the first:

  • bootfs — small FAT/FAT32 drive (often a few hundred MB). This is where you copy stonePi.
  • rootfs — large ext4 volume. Windows may say it must be formatted. Do not format it. Close that dialog.

If you only see the “needs format” prompt and no drive letter for boot: eject the card, unplug the reader, plug it back in. Check This PC for a new drive (sometimes named bootfs or boot). In Disk Management you should see a FAT partition you can assign a letter to if it has none.

Layout on the boot partition

bootfs/
  stonePi/
    apps/
    deploy/
    packages/
    scripts/
    README.md
    …

Do not copy .venv folders (Windows-only). Skip dist/, .git/, and local data/ if present.

Helper on Windows (boot drive E: example):

scripts\copy-to-sd.bat E:\

Boot partition still missing? Use the network instead

You can flash and boot the Pi with no files on the SD, then copy StonePi over SSH from your PC.

  1. Flash OS with SSH + Wi‑Fi/Ethernet as usual, boot the Pi, SSH in.
  2. On the Pi, create a destination folder:
mkdir -p ~/stonePi

From your Windows PC (PowerShell), with the unzipped project at e.g. C:\Users\You\stonePi:

scp -r C:\Users\You\stonePi\* adam@stonepi.local:~/stonePi/

Replace adam and the path. Then SSH in and run the installer from ~/stonePi (next steps).

cd ~/stonePi
sudo bash deploy/install.sh --hostname stonepi

SSH in

Replace adam with the username you set in Imager.

Connect

ssh adam@stonepi.local

If .local does not resolve yet, use the Pi’s IP from your router.

Confirm the copy landed

ls /boot/firmware/stonePi/deploy/install.sh

On older images the path may be /boot/stonePi/....

Run the installer

Boot is FAT, so use bash — execute bits are not reliable. First run can take several minutes (pip + Chromium for EventTrakr).

One-shot from boot

sudo bash /boot/firmware/stonePi/deploy/install.sh --hostname stonepi

Or copy home first (cleaner for re-runs)

cp -a /boot/firmware/stonePi ~/stonePi
cd ~/stonePi
sudo bash deploy/install.sh --hostname stonepi

What the installer does

  • System packages (Python, Nginx, Avahi, Cockpit, Playwright libs)
  • Tree → /opt/stonepi
  • /etc/stonepi/*.env and /var/lib/stonepi (kept on re-run)
  • Python venvs + dependencies
  • Systemd units enabled for boot
  • Nginx path routing and stonepi.local
  • Cockpit enabled

After it finishes

stonepi status

First-boot setup

Secure the admin account, then optionally add keys and glance at Overview.

Do these now

Default is trusted LAN. Flip to Internet-facing only when you put StonePi behind a tunnel or public HTTPS — apps tighten on the next request, no restart. Details: deploy/SECURITY.md.

Backup USB

Treat the stick as sensitive — it holds application data.

Once

Backup runs when you plug in a USB labelled STONEPI-BACKUP (no weekly timer).

  1. Format a USB disk with label STONEPI-BACKUP (see deploy/backup/RESTORE.md).
  2. Plug it into the Pi — apps pause briefly while data is copied, then start again.
  3. Optional manual run:
sudo systemctl start stonepi-backup
sudo journalctl -u stonepi-backup -n 40 --no-pager

You’re done

StonePi should come back after reboot. Re-running the installer is safe — it keeps databases and existing env files.

cd ~/stonePi   # or /opt/stonepi after first install
sudo bash deploy/install.sh --hostname stonepi

Common snags on a fresh OS.

SymptomWhat to try

“Welcome to nginx”Re-run installer, or remove sites-enabled/default and reload nginx
502 Bad Gatewaystonepi status then sudo journalctl -u stonepi-auth -e
