# Changelog — AgentLink

## 0.5.0 — 2026-10-25

### Added
- **AgentLink** (`stonepi-agentlink`, port 8015, loopback): the one way in for agents and agent devices (`ideation/muse.md`, `ideation/pebble.md`). Bindings (one device ↔ one person, tokens stored as SHA-256), a tool registry (`get_status` first), per-binding tool switches, and `invoke()` checking binding → tool → params → policy → owner still enabled, with every call in an audit log (`stonepi_audit`, 90 days, never what was said).
- **Pebble adapter**, [Pebble protocol v1](https://github.com/ast0ne1/pebble-esp32/blob/main/PROTOCOL.md): claim codes (LAN only, 15 minutes, handed out once), config with a `rev`, moods (happy, content, sleepy, worried, upset, proud), ask, and unpair. `X-StonePi-Path` from nginx decides LAN or away; without it the stricter away rules apply.
- **Ask pipeline:** faster-whisper on the Pi → the device's enabled read tools as facts → platform AI `pebble.reply` → piper → 22.05 kHz WAV, one ask at a time. Speech engines are optional installs (`stonepi-speech-setup`); without them asks answer `503 speech_unavailable`. `tools/speech_check.py` times both.
- Signed internal API for Notify → Sidekick: overview, claim, device settings, revoke.
- **Whisper knows StonePi's names**: an initial prompt with StonePi, Pebble and the app names (so it stops hearing "Stone Pie"); `AGENTLINK_WHISPER_HINT` adds more, such as people's names.
- **Fixed: Pebbles at home couldn't pair** ("Pair Pebble at home"). Uvicorn's proxy handling replaced nginx's loopback address with the device's, so AgentLink ignored nginx's lan/away label and treated every request as away. Uvicorn now runs with `proxy_headers` off; AgentLink reads `X-Real-IP` itself, from loopback only.
- **Speech warm-up**: both models load in the background when AgentLink starts, so the first ask after a restart isn't slower (on the Pi 4 the cold first ask took ~27 s of loading).
- **Weather:** `get_weather` reads the weather at home from Notify (the household's place, Car Thing → Look): now, the next hours every 3 h and the next 3 days with rain chances. Nothing personal, so it's on for new and existing Pebbles; `get_today` includes it. The prompt has Pebble answer for home only and say where to set the place when there isn't one.
- **Phase 2 read tools:** `get_today`, `get_events`, `search_events`, `get_reminders`, `get_notices`, `get_news_briefing`, `search_news`, calling each app's signed `/api/internal/agent` for the binding's user. Off for a new binding; each re-checks the user's app grant through Auth (`no_access` otherwise). `get_today` includes a section only when its tool is on and the app is granted.
- **Asks use them:** the enabled read tools run in parallel; a short planner call picks searches only when the question names something to look up. Facts up to 9,000 characters.
- **Voices:** eleven English piper voices from the pinned rhasspy release; choose (download in the background) and preview through the internal API; the choice lives in `settings.json`.
- **Mood redesign** (same seven moods, same `/mood` reply, no firmware change): upset at once for something critical (Auth down, backup failed, disk full); worried for a problem lasting 5 minutes, only in core StonePi or apps the owner has; sleepy for quiet hours or a battery under 20% ("I need charging"); proud for 5 minutes after an answer; curious for a Pinboard notice under 6 hours old or today's paper out in the last hour; happy for an event later today ("Jazz in the park at 19:00") or a chat in the last 3 hours; otherwise content. Overdue reminders become the caption. A new mood holds a minute before the face changes (upset and proud show at once). No more sleepy-from-neglect. Owner signals only through tools switched on and apps granted, cached 2 minutes per device.
- **Quiet hours**, household-wide in `settings.json` (with the voice): signed `POST /pebble/settings`; the overview includes them and each Pebble's current mood and reason.
- **Pebble knows itself and the owner's apps:** the ask prompt adds an About-you block (name, owner, mood and why, battery, home or away, quiet hours) and an app guide (each of the owner's apps with what Pebble can read and whether it's on). "How are you?" is answered from the mood its face shows; a question needing a switched-off tool gets "switch it on in Sidekick".
- **News by category:** `get_news_briefing` and `search_news` take an optional `category`. The planner also picks a news category from the question ("what's in the news in sport?"), and the prompt has Pebble name today's categories and ask which one when the question is broad.
- **Follow-ups:** the last question and answer on each Pebble are kept in memory for 2 minutes (never on disk or in the audit log), so answering Pebble's question ("sport") continues the conversation.
- **Events by time and kind:** `get_events` takes `when` (today, tonight, tomorrow, this_weekend, this_week, next_week) and `category`; the planner picks them from the question or a follow-up ("just the community ones"), and the prompt has Pebble cover everything in the window, offering to narrow down when there are more than four.
- **Fixed: admins' Pebbles couldn't read apps they'd never been granted explicitly.** StonePi gives admins every app, but AgentLink only counted saved grants, so an admin's event (or other) reads came back `no_access` and Pebble had nothing to say. Admins now have every user app here too.
- **Fixed: replies cut off mid-sentence.** Longer replies (up to 400 tokens, up to 5 sentences when reading headlines or events) always end on a full sentence, even when the model runs out of room; the on-screen caption (200 bytes by protocol) ends on a whole word with "…" while the audio says it all.
